## 0. このツールの立ち位置（画面にも明記する）

- 本ツールは **BI の入力補助・ADL利得の「見込み」表示・測定/提出スケジュールの見張り** までを担う**モック**です。
- **正式なADL利得の確定計算（調整係数によるリスク調整）と、LIFEへの提出は LIFE 本体側の仕事**です。本ツールの数値は**確定値ではありません**。
- データは**このブラウザ内（localStorage）にのみ**保存され、外部送信はありません（既存の注記文言を踏襲）。

> 画面表示文（案）:
> 「※本画面のADL利得・加算判定は**見込み**です。確定値・LIFE提出はLIFE本体で行ってください。データはこのブラウザ内にのみ保存されます。」

## 2. ① データモデル

### 2.1 既存との関係

- 既存 `state = { users:[…], records:[…], seededAt }` に **`bi:[]` を1本追加**する。
- 既存 `users[]` の `adl/cog/stab`（＝ケアスコア用の内部値）とは**別物**。BIはこの値を上書きしない（混同防止）。
- 既存の利用者を `userId` で参照（利用者管理と同一データ）。

### 2.2 BI測定レコード（`state.bi[]` の1要素）

```
BiAssessment {
  id:          "bi" + 連番/時刻,
  userId:      "u01",              // 既存 users[].id を参照
  phase:       "initial" | "followup",   // 初回(利用開始月) / 6か月後(7か月目)
  measuredMonth: "2026-01",        // 測定月(YYYY-MM)。提出期限計算の基準
  items: {                          // 10項目の点数（配点表に沿う値のみ許可）
    feeding, transfer, grooming, toilet, bathing,
    mobility, stairs, dressing, bowels, bladder
  },
  total:       0-100,               // items合計（保存もするが表示時に再計算し整合を担保）
  note:        "特記事項",
  status:      "draft|submitted|reviewed|approved|rejected", // 既存STAGESを再利用
  history:     [ { stage, by, at, comment } ]                 // 既存と同形
}
```

**設計上の判断（承認いただきたい点）**

1. **1レコード＝1時点の測定**。同一利用者は `initial` と `followup` を各1件持つ想定。
   - 3回目以降（次周期）は将来拡張。まずは 初回／6か月後 の2枠に絞る。
2. **合計は導出値**だが、集計を軽くするため保存もする（表示時に `items` から再計算して検算）。
3. `phase` と `measuredMonth` は両方持つ。`phase` は変化計算の対（初回↔6か月後）を結ぶキー、`measuredMonth` は期限計算の基準。

### 2.3 集計（画面表示のための導出ロジック、保存しない）

- **個人利得** `gain(user) = total(followup) − total(initial)`（両方が揃っている利用者のみ）。
- **事業所平均利得** `avgGain = mean( gain(user) )`（両方揃い＋集計対象ステータスの利用者が母集団）。
- **加算見込み** `avgGain ≥ 3 → (Ⅱ)見込み ／ ≥ 1 → (Ⅰ)見込み ／ それ未満 → 未達`。
- **集計対象ステータス（要確認）**: 既定は **`reviewed`（リーダー確認済）以上** を「確定した測定」とみなし集計対象にする。`draft/submitted/rejected` は対象外。

### 2.4 スケジュール導出

- **次回BI測定月** `nextMonth = addMonths(直近measuredMonth, 6)`。
  - `followup` があればそれ基準、なければ `initial` 基準（＝7か月目相当）。
- **LIFE提出期限** `deadline(measuredMonth) = measuredMonthの翌月10日`（仮置き・定数化）。
- **アラート判定**（今日基準）:
  - 🔴 **超過**: 提出期限 < 今日、かつ当該測定が未確定/未提出扱い
  - 🟡 **間近**: 期限まで14日以内（しきい値は定数化）
  - ⚪ **次回測定が近い**: 次回測定月 ≤ 今月+1

### 2.5 マイグレーション（既存localStorageの保護）

- `STORE_KEY` は据え置き、**バージョンは上げない**（既存デモ編集を消さない）。
- `load()` 時に `d.bi` が無ければ `d.bi=[]` を**バックフィル**。
- デモ用BIサンプル（後述）は「BIが空のときだけ」投入し、既存編集を尊重。
- 「デモデータ初期化」ボタン押下時は users/records と同様に BI もサンプルへ戻す。

## 3. ② 画面フロー

### 3.1 追加ナビゲーション

既存タブ（ダッシュボード/利用者管理/リハビリ記録/承認ワークフロー/分析レポート）に
**「📋 BI評価」タブを1つ追加**。既存ワークフロー/レポートは壊さない。

### 3.2 BI評価タブ（一覧）

```
[AIパネル] 事業所平均利得と加算見込みサマリー（見込みである旨を明記）
[ツールバー] 🔍検索 / 状態フィルタ / 「＋ BI測定を記録」
[テーブル]
  利用者 | 初回(月/点) | 6か月後(月/点) | 変化(後−前) | 加算寄与 | 次回測定月 | 提出期限 | 状態
  - 変化はプラス緑/マイナス赤。未測定は「—」
  - 提出期限は 🔴超過/🟡間近 をチップ表示
  - 行クリックで詳細モーダル
```

### 3.3 入力モーダル「BI測定を記録」

- 利用者選択（既存 `users` から）／`phase`（初回・6か月後）／測定月。
- **10項目を選択式**（各項目その項目で許可された点数のみ：ラジオ/セグメント）。選択肢に一言説明。
- **合計を即時ライブ計算**（0–100）。
- 特記事項（任意）。
- フッター: **［下書き保存］／［提出する］**（＝担当が入力→提出）。
- 入力アシスト: 直近の同利用者データがあれば初期表示（任意・将来）。

### 3.4 詳細モーダル

- 10項目の内訳・合計、初回↔6か月後の対比（対がある場合）、**この利用者の利得（見込み）**。
- 承認履歴（既存 `history` の時系列表示を再利用）。
- **ワークフロー操作ボタン**（役割に応じて活性/ロック）。

### 3.5 承認フロー（既存を再利用）

- 状態機械・役割は既存 `STAGES`（下書き→提出→確認→承認）と 担当/リーダー/管理者 を**そのまま再利用**。
- BIの実運用ゲートは **担当が入力→提出（submitted）→ リーダー＝機能訓練指導員が確認（reviewed）**。
  - `reviewed` で「集計・スケジュールの確定測定」とみなす（2.3参照）。
  - 管理者承認(`approved`)まで進めることも可能（既存挙動を壊さないため状態機械は共通）。承認は任意。
- **実装方針（要承認）**: 既存の `advance/reject/reopen` は現状 `state.records` 専用。
  - 案A（推奨・低リスク）: これらを「対象コレクションを受け取る」形に**小さく一般化**し、records/bi 双方で共有。
  - 案B: BI画面内に同等の操作関数を薄く複製（`history`形状は共通）。
  - まず**案A**で進め、リグレッションが出れば案Bへ退避。

### 3.6 ダッシュボードへの追記

- 既存の「⚠️ 要フォロー」カードの並びに **「⏰ BI測定・LIFE提出アラート」カード**を追加。
  - 🔴超過 / 🟡間近 / 次回測定間近 を一覧。クリックで当該利用者のBI詳細へ。
- KPI に「加算見込み（Ⅰ/Ⅱ/未達）」バッジを1枚追加（見込みである旨のツールチップ）。

### 3.7 分析レポートへの追記（任意・後回し可）

- 事業所平均利得、利得分布、加算しきい値(1/3)への到達状況を可視化。
- スコープが膨らむため**最終ステップ**に回し、まずは 3.2–3.6 を優先。

## 4. ③ スコープの線引き（IN / OUT）

### ✅ IN（本ツールで作る）

- 利用者ごとのBI記録（標準配点10項目・合計100点・**根拠コメント必須**）。
- 初回／6か月後の記録と **変化（後−前）** 表示。
- **事業所平均利得**の算出と **加算(Ⅰ)≥1／(Ⅱ)≥3 の「見込み」表示**（非確定・非調整を明記）。
- **次回BI測定月／LIFE提出期限（測定月の翌月10日・仮置き）** の算出と、ダッシュボードでの**期限アラート**。
- 既存**承認ワークフロー（担当入力→リーダー確認）**と役割の再利用。
- 既存**利用者データの参照**。
- 「見込みである／ブラウザ内保存のみ」の**画面明記**。

### 🚫 OUT（作らない・LIFE本体や制度側の仕事）

- 正式なADL利得の**確定計算（調整係数・リスク調整）**。
- **LIFEへの実提出・データ連携**。
- 加算の**実際の算定可否判定**（利用者数要件・6か月以上利用・提出実績などの制度要件充足チェック）。
- **単位数・請求額の計算**。
- サーバ保存・多端末同期・認証（引き続き localStorage のみ）。
- 3回目以降の測定周期の本格管理（初回/6か月後の2枠に限定。将来拡張）。
